정리본 1. Introduction

자료구조가 무엇인지, 왜 선택이 성능을 좌우하는지, 이 강의에서 무엇을 배우는지.

1. 자료구조(Data Structure)란?

자료구조(Data Structure): 데이터를 조직하고 효율적으로 관리하는 방법.

Program = Data Structure + Algorithm

프로그램이 느릴 때 원인은 두 가지 중 하나다. 나쁜 알고리즘이거나, 부적절한 자료구조거나. 그런데 실제로는 부적절한 자료구조가 더 흔한 원인이다.

  • Data Structure(자료구조)는 "데이터를 어떻게 저장할 것인가"를 결정한다 → 메모리 구조, 연산 방식, 성능 특성.
  • Algorithm(알고리즘)은 "데이터를 어떻게 처리할 것인가"를 결정한다 → 단계별 절차, 연산 조합, 최적화 방식.
  • 둘은 독립적이지 않다. 자료구조를 고르면 쓸 수 있는 알고리즘이 정해진다.

예제 · 자료구조가 알고리즘을 제한한다

같은 "정렬" 작업도 자료구조에 따라 선택지가 달라진다.

  • 배열(Array): Bubble, Selection, Insertion, Merge, Quick, Heap — 6가지 이상 선택 가능.
  • 연결 리스트(Linked List): Merge, Insertion만 효율적. QuickSort는 Random Access(임의 접근)가 불가능해서 사실상 제외.
  • Binary Search Tree(이진 탐색 트리): In-order Traversal(중위 순회) 하나면 자동으로 정렬됨. 별도 정렬 알고리즘이 필요 없다.

→ 올바른 자료구조 선택이 곧 올바른 알고리즘 선택이다.

3. 왜 중요한가: 100만 개 검색 실험

100만 개 데이터에서 특정 값 하나를 찾는다고 하자. 자료구조만 바꿨을 뿐인데 결과는 이렇게 갈린다 (연산당 1ns 가정).

자료구조시간복잡도실제 비교 횟수소요 시간
배열 + 선형 탐색O(n)평균 500,000회0.5ms
이진 탐색 트리(BST, 균형)O(log n)평균 20회0.00002ms
해시 테이블O(1)평균 1회0.000001ms
  • 배열 vs BST → 25,000배 차이, 배열 vs Hash → 500,000배 차이.
  • 데이터가 작으면(n < 100) 무관하지만, 커질수록 격차는 빠르게 벌어진다(비율 ≈ n/log n). n = 100K에서 배열은 약 100배, n = 1M에서는 약 1000배 느리다.

같은 연산도 구조마다 비용이 다르다

"중간에 삽입" 한 번을 예로 들면:

  • 배열: 위치 찾기 O(n) + 오른쪽 원소 전부 Shift O(n) → O(n).
  • 연결 리스트: 위치 찾기(순회) O(n) + 포인터 수정 O(1) → O(n). 위치를 알고 있다면 삽입 자체는 O(1)이고 shift가 없어 배열의 중간 삽입보다 유리할 수 있다.
  • 트리에서 중간 데이터 찾기: 이진 탐색 O(log n) → 배열 대비 100배.

문제 해결 방식 자체가 자료구조에 의존한다.

4. 예제로 보는 선택의 차이: 성적 조회 시스템

요구사항: 학생 1000명, 학번을 입력하면 성적 반환. 같은 요구사항을 세 가지 자료구조로 설계해 보자.

방안구조검색 방식평균 비교
A. 배열[성적1][성적2]…[성적1000]처음부터 끝까지 순서대로 비교O(n) ≈ 500회
B. BST중앙값 학번 500이 루트, 좌우로 분기 (균형 트리 가정)크기 비교로 절반씩 제외O(log n) ≈ 10회
C. 해시 테이블Hash Function으로 학번 → 인덱스계산 후 바로 접근O(1) ≈ 1회
// A. 배열
for (i = 0; i < 1000; i++) if (id[i] == target) return score[i];

// B. BST
if (target < node.key) search(node.left); else search(node.right);

// C. 해시 테이블
return hashTable[hash(target)];

같은 문제인데 500회 vs 10회 vs 1회 — 자료구조만으로 50배 이상 차이가 난다.

5. 어떤 자료구조를 고를까

정답이 하나로 정해진 것이 아니라, 문제의 조건을 보고 트레이드오프를 따지는 과정이다. 세 가지 질문을 순서대로 던지면 된다.

선택 기준 3단계

  1. 가장 빈번한 연산이 무엇인가?
    • 검색 위주 → Hash Table / BST (예: 전화번호부, 성적 조회)
    • 최대/최소가 자주 필요 → Heap (예: 작업 우선순위, CPU 스케줄링)
    • 삽입/삭제 + 순서 유지 → AVL Tree (예: 순위 변동, 실시간 업데이트)
  2. 메모리 제약이 있는가?
    • 제한 있음 → Linked List (데이터 수에 비례하는 메모리 - hash table처럼 여유 bucket 불필요, 예: 임베디드)
    • 충분함 → Hash Table (예: 클라우드, 고성능 서버)
  3. 최악의 경우 보장이 중요한가?
    • 중요(실시간) → Merge Sort O(n log n) 보장 (예: 의료, 항공, 금융)
    • 평균만 중요 → Quick Sort 평균 O(n log n) (예: 일반 데이터 처리)

5.1 연산별 성능 요약

자료구조검색삽입삭제순서 유지사용 시기

6. 강의 로드맵과 학습 전략

L2(C++)와 L3(알고리즘 분석)이 모든 것의 토대. L3, L8, L10에서 개념적 도약이 온다.
  • L2 C++ 기초: 포인터, 동적 할당, 메모리 관리 — 자료구조 구현의 기초.
  • L3 알고리즘 분석: Big-O 표기법, 시간/공간 복잡도 — 성능 평가의 기준.
  • L4–5: 선형 자료구조 3종, 트리 기본 성질.
  • L6–9: 순회와 트리 복원, 우선순위 큐/힙, 정렬 5종, BST.
  • L10: AVL Tree — Self-Balancing(자가 균형)과 Rotation(회전).

6.1 학습 목표 4단계

  1. 개념 이해 — List, Stack, Queue, Tree가 무엇인지 정의를 안다.
  2. 기본 연산 구현 — Insert, Delete, Search를 코드로 쓴다.
  3. 성능 분석 — 각 연산의 시간/공간 복잡도를 Big-O로 계산한다.
  4. 선택과 적용 — 주어진 문제에 어떤 자료구조를 쓸지, 왜 그것인지 설명한다. 이 강의의 최종 목표.

6.2 AI 활용 기준

  • 허용: 개념 질문("Stack이 뭐야?"), 구현 예시 요청, 강의 복습, 디버깅.
  • 금지: 시험 중 사용, AI가 쓴 코드 그대로 제출, 이해 없이 복사.
  • "어떤 자료구조를 써야 하는가"를 판단하는 능력이 진짜 경쟁력이다.

7. Quiz

Q1같은 데이터로 배열과 BST를 구성했을 때, 검색 성능이 다른 이유는?
힌트

핵심은 "다음에 어디를 볼지 아는가"다. 배열은 원소의 위치 정보가 없어 처음부터 훑어야 하고, BST는 크기 비교 한 번으로 탐색 범위를 절반으로 줄인다.

정답

개념은 힌트 참고.

  1. 배열: target이 어디 있는지 알 수 없어 평균 n/2회 비교 → O(n).
  2. BST: 루트와 비교해 좌/우 하나를 버리는 것을 반복 → O(log n).
  3. 같은 데이터인데 구조가 다르면 쓸 수 있는 탐색 절차가 달라진다.
정답: 자료구조가 연산 방식을 결정하기 때문 — 배열은 선형 탐색 O(n), BST는 이진 탐색 O(log n)이 가능하다.
Q2"자료구조 선택이 알고리즘을 결정한다"는 무슨 의미인가?
힌트

섹션 1의 정렬 예시를 떠올려 보자. 배열에서는 6가지 정렬이 가능하지만 연결 리스트에서는 QuickSort가 Random Access 부재로 비효율적이고, BST는 순회만으로 정렬된다.

정답

개념은 힌트 참고.

  1. 배열 → Random Access 가능 → Bubble/Quick/Merge 등 대부분의 정렬 사용 가능.
  2. 연결 리스트 → Random Access 불가 → Merge, Insertion만 효율적.
  3. BST → In-order Traversal 자체가 정렬 → 별도 알고리즘 불필요.
정답: 같은 문제라도 자료구조마다 필요한(가능한) 알고리즘이 다르다. 자료구조를 고르는 순간 알고리즘 후보가 정해진다는 뜻이다.
Q3왜 배열과 연결 리스트가 둘 다 필요한가? 연결 리스트가 더 나은가?
힌트

각각의 장점이 상충(trade-off)한다: Random Access O(1) ↔ 동적 크기.

정답

개념은 힌트 참고.

  1. 인덱스로 바로 접근해야 하는 작업 → 배열이 압도적.
  2. 크기를 예측할 수 없고 삽입/삭제가 잦은 작업 → 연결 리스트가 유리.
  3. 어느 한쪽이 모든 상황에서 우월하지 않다.
정답: 아니다. 둘은 트레이드오프 관계라 문제의 특성에 따라 골라야 한다.
Q4100만 개 데이터 검색에서 배열 vs BST 차이가 수만 배가 되는 이유는?
힌트

O(n)과 O(log n)에 n = 1,000,000을 대입해 보자. log₂(10⁶) ≈ 20.

정답

개념은 힌트 참고.

  1. 배열 선형 탐색: 평균 n/2 = 500,000회 비교.
  2. BST 이진 탐색: log₂(100만) ≈ 20회 비교.
  3. 500,000 / 20 = 25,000 → 약 2만 5천 배 차이.
정답: O(n) = 50만 회 vs O(log n) = 20회. 데이터가 클수록 차이는 더 벌어지므로 빅데이터에서는 자료구조가 성능을 사실상 결정한다.
Q5Hash Table이 검색 O(1)인데도 모든 곳에 쓰이지 않는 이유는?
힌트

O(1)의 대가를 생각해 보자: 해시 충돌(Collision), 순서 정보 소실, 메모리 오버헤드.

정답

개념은 힌트 참고.

  1. Collision 처리 로직이 복잡하다.
  2. 데이터의 순서를 유지하지 못한다 → 순서가 필요하면 BST.
  3. 메모리 오버헤드가 있다 → 메모리가 빠듯하면 배열.
정답: Collision 처리 비용, 순서 없음, 메모리 오버헤드 때문에 요구사항에 따라 BST나 배열이 더 나은 선택이 된다.
