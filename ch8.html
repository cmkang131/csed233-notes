2. Bubble Sort(버블 정렬)

아이디어

  • -th pass에서 -th 최솟값이 -th 위치로 '떠오름'
  • 인접 원소 비교 → 순서 뒤바뀐 쌍 swap
  • Early termination: 한 pass에서 swap 0번 → 이미 정렬됨 → 종료

복잡도

Case 시간
Best (이미 정렬) — early termination
Average / Worst — 비교, swap
  • 용도: 정도 소규모만. 실무 거의 안 씀.

3. Selection Sort(선택 정렬)

아이디어

  • -th pass에서 unsorted 부분의 최솟값 찾아 와 swap
  • pass당 swap 최대 1번 → swap 비용 중요한 상황에 유리

복잡도

  • 비교 횟수는 항상 : best = average = worst
    • 이유: 매 pass마다 나머지 전체를 스캔해 최솟값 탐색
  • Swap 횟수는 번 (bubble보다 훨씬 적음)

4. Insertion Sort(삽입 정렬)

아이디어

  • -th pass에서 를 이미 정렬된 에 올바른 위치에 삽입
  • 카드 정렬 직관: 한 장씩 뽑아 손에 있는 정렬된 카드에 꽂음

복잡도

  • Best : 이미 정렬된 경우 → 각 원소 비교 1번
  • Average / Worst : swap

실전 가치

  • 작은 ()에선 Merge/Quick보다 빠름 (상수항 작음)
  • → Merge/Quick sort에서 recursion base로 사용 (hybrid 기법)

6. Merge Sort(병합 정렬)

Divide & Conquer

  1. Divide: 배열을 반으로 분할
  2. Conquer: 각 반을 재귀적으로 정렬
  3. Combine: 두 정렬된 리스트를 merge

Merge 연산 자체

  • 두 정렬 리스트 를 merge
  • 두 포인터로 맨 앞 원소 비교 → 작은 쪽을 output에 추가
  • 한쪽 소진 시 나머지 그대로 append

단점 & 최적화

  • 추가 메모리 필요 (in-place 어려움)
  • Stable ✓
  • Worst case도 ✓ → 보장 필요 시 유리
  • 최적화: 일 때는 insertion sort 사용 (상수항 작음)

Non-recursive (Bottom-up)

  • Size 1 segment에서 시작 → pairwise merge → size 2 → size 4 → ...
  • Downward pass 제거, 직접 위로 병합

7. Quick Sort(퀵 정렬)

Divide & Conquer (Partition 기반)

  1. Pivot(피벗) 선택
  2. Partition: pivot 기준 3 그룹
    • Left: key < pivot
    • Pivot
    • Right: key ≥ pivot
  3. 재귀: left, right 각각 정렬
  4. Combine: sorted(L) + pivot + sorted(R) (concat 자체는 거의 free)

Partition 방법

Method 2 (In-place)

  • 두 포인터 L, R (양 끝에서 시작)
  • L: pivot 이상인 값 탐색 (왼→오)
  • R: pivot 이하인 값 탐색 (오→왼)
  • L, R 서로 다른 쪽이면 swap, 마주치면 종료 → pivot과 R 위치 swap
  • 추가 메모리 거의 없음 → cache friendly

실전 선택 기준

  • Quick sort: 평균 가장 빠름 (상수항 작음, cache-friendly) → 일반적인 경우 1순위
  • Merge sort: worst-case 보장 + stable 필요 시 (예: 외부 정렬, linked list)
  • Heap sort: 실시간 시스템 (worst 보장 + 공간)
    • quick sort는 worst 이라 실시간엔 위험

Quick의 cache 이점

  • In-place → 같은 배열 접근 → cache coherence
  • Merge sort는 별도 buffer 왕복 → cache miss 발생
