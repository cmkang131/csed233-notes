정리본 10. AVL Tree

Balance Factor · 4가지 회전 유형 · Insert/Delete 재균형.

1. 왜 AVL이 필요한가

정리본 9에서 봤듯, 편향 BST는 높이 n으로 모든 연산이 이 된다. 높이를 강제로 제한하면 모든 연산을 으로 보장할 수 있다 — 그게 자동 균형 트리다.

정의 · AVL Tree

다음 두 조건을 모두 만족하는 이진 트리:

  1. BST 성질: 왼쪽 < 부모 < 오른쪽.
  2. Height-Balanced 성질: 모든 노드에서 좌우 서브트리 높이 차가 1 이하.
공식 · 높이와 Balance Factor

AVL 조건: 모든 노드에서 . |bf| ≥ 2이면 불균형 → 회전 필요.

  • bf = −1: 오른쪽이 1 높음 (OK) · bf = 0: 완전 균형 · bf = +1: 왼쪽이 1 높음 (OK)

이 조건 덕분에 n개 노드의 AVL 트리는

를 만족해 편향이 불가능하다.

2. 불균형의 4가지 유형과 회전

노드 x에서 |bf(x)| = 2가 발견되면, 무거운 쪽 자식의 bf 부호로 유형을 판정한다.

유형판정의미해결
LLbf(x) = +2, bf(왼쪽 자식) > 0왼쪽-왼쪽으로 무거움우회전 1회
RRbf(x) = −2, bf(오른쪽 자식) < 0오른쪽-오른쪽으로 무거움좌회전 1회
LRbf(x) = +2, bf(왼쪽 자식) < 0왼쪽 자식의 오른쪽이 무거움자식 좌회전 → 부모 우회전
RLbf(x) = −2, bf(오른쪽 자식) > 0오른쪽 자식의 왼쪽이 무거움자식 우회전 → 부모 좌회전

2.1 Single Rotation 메커니즘

Left Rotation은 이 그림의 좌우 대칭
rotateRight(z):
  y = z.left        // 나중에 접근 못 하니 먼저 저장
  z.left = y.right
  y.right = z
  update_height(z)  // 아래쪽(자식이 된 z)부터
  update_height(y)
  return y          // 새 서브트리 루트

2.2 Double Rotation — LR 타입

예제 · LR: 왼쪽은 무거운데(bf=+2) 왼쪽 자식은 오른쪽이 무거움(bf=−1)
  1. 자식 좌회전 — B를 기준으로 좌회전하면 A–C–B가 일직선 LL 형태가 된다. 
        A(+2)          A(+2)
   /              /
  B(−1)    →     C(+1)
   \            /
    C          B
  2. 부모 우회전 — A를 기준으로 우회전하면 C가 새 루트가 되고 균형 복구. 
        A(+2)              C(0)
   /                  / \
  C(+1)      →       B   A
 /
B

RL 타입은 정확히 대칭: "자식 우회전 → 부모 좌회전".

암기법

Double rotation의 첫 회전은 안쪽으로 꺾인 다리를 펴는 작업이다. 펴진 뒤(LL/RR)에는 single rotation 한 번으로 끝.

3. Insert — 삽입 후 최대 1회 회전

  1. 표준 BST Insert: 삽입 위치를 찾아 리프에 노드를 추가한다.
  2. 상향 조정: 삽입 노드에서 루트까지 올라가며 높이와 bf를 갱신하고, |bf| = 2인 첫 노드에서 유형에 맞는 회전 1회. Insert는 이 1회로 끝난다.
예제 1 · Insert 3, 2, 1 → LL 
   3            3(+2)               2
  /      →      /        우회전 →    / \
 2            2(+1)                1   3
             /
            1
예제 2 · 이어서 Insert 4, 5 → RR (pivot: 3) 
    2                2                  2
   / \              / \                / \
  1   3      →     1   3(−2)   좌회전→ 1   4
       \                \                 / \
        4                4(−1)           3   5
                          \
                           5

시간복잡도: 삽입 + 회전 위치 탐색 + 회전 → 총 .

4. Delete — 연쇄 불균형이 가능하다

  1. 표준 BST Delete: leaf / 자식 1개 / 자식 2개(successor) 경우 처리.
  2. 불균형 확인: 삭제 위치의 부모부터 루트까지 bf 재계산.
  3. 재균형: 불균형 발견 시 회전. 회전으로 서브트리 높이가 줄면 불균형이 위로 전파될 수 있어 루트까지 계속 확인한다.
Insert와 Delete의 차이 — 시험 단골

Insert는 회전 최대 1회로 끝나지만, Delete는 회전 후 서브트리 높이가 1 줄어들면서 상위 노드에 새 불균형을 만들 수 있다 — 연쇄 불균형(cascading imbalance), 회전이 여러 번 필요할 수 있다.

예제 · Delete(90)에서 연쇄 회전
  1. 삭제: 90은 leaf라 그냥 제거. 
                50(+1)
          /        \
       30(+1)       80(+1)
      /   \        /    \
    20     40    70      90 ← 삭제
   /  \     \   /
 10   25    45 60
 /
5
  2. 1차 불균형 (노드 80): 오른쪽이 비어 bf(80) = +2 (LL) → 우회전. 서브트리 루트가 70으로, 높이가 2 → 1로 감소. 
         70
    /  \
  60    80
  3. 2차 불균형 (루트 50): 높이 감소가 위로 전파 → bf(50) = h(30) − h(70) = 3 − 1 = +2 (LL) → 루트에서 우회전. 
              30
        /    \
      20      50
     /  \    /  \
   10   25 40    70
  /        \   /  \
 5         45 60   80

최종 루트 30의 양쪽 높이가 2로 같아져 bf = 0, 완전 균형 회복.

5. 연습: Insert 3, 2, 1, 4, 5, 6, 7 — 회전 횟수 세기

순서대로 삽입하며 매번 bf를 확인한다. 정답: 총 4회 회전.

  1. Insert 3, 2 — 3 → 2. 불균형 없음.
  2. Insert 1 → LL 불균형 (pivot 3) — 우회전(1회째). 루트가 2로: 2 / 1,3.
  3. Insert 4 — 3의 오른쪽에 부착. bf(3) = −1, 균형 유지. 회전 없음.
  4. Insert 5 → RR 불균형 (pivot 3) — 5는 4의 오른쪽에 붙고 bf(3) = −2. 좌회전(2회째): 2 / 1, 4(3,5).
  5. Insert 6 → 루트에서 RR 불균형 (pivot 2) — 6은 5의 오른쪽에 붙고, 오른쪽 서브트리 높이가 2가 되어 bf(2) = −2. 루트 좌회전(3회째): 4 / 2(1,3), 5(–,6).
  6. Insert 7 → RR 불균형 (pivot 5) — 7은 6의 오른쪽에 붙고 bf(5) = −2. 좌회전(4회째): 최종 4 / 2(1,3), 6(5,7), 모든 노드 균형.
채점 포인트

회전 "횟수"뿐 아니라 어느 노드가 pivot인지, LL/RR/LR/RL 중 무엇인지를 함께 쓰는 문제가 많다. bf 부호로 유형을 먼저 판정하자: bf = +2면 왼쪽이 무거운 것(LL 또는 LR), −2면 오른쪽(RR 또는 RL).

힌트

섹션 5의 단계를 그대로 따라가며 |bf| = 2가 되는 순간을 센다.

정답

개념은 힌트 참고.

  1. Insert(1): LL → 우회전 1회 (pivot 3).
  2. Insert(5): RR → 좌회전 1회 (pivot 3).
  3. Insert(6): RR → 좌회전 1회 (pivot = 루트 2).
  4. Insert(7): RR → 좌회전 1회 (pivot 5).
정답: 총 4회 (LL 1회 + RR 3회).
Q2Balance Factor가 2 이상이 되는 것을 어떻게 방지하는가?
힌트

모든 Insert/Delete 직후에 하는 공통 작업.

정답

개념은 힌트 참고.

정답: Insert/Delete 후 삽입·삭제 지점에서 루트까지 거슬러 올라가며 bf를 재계산하고, |bf| > 1을 발견하는 즉시 회전으로 복구한다.
Q3LL과 LR은 모두 왼쪽이 무거운데(bf = +2) 처리가 다른 이유는?
힌트

왼쪽 자식의 bf 부호를 본다. 안쪽으로 꺾인 형태는 한 번의 회전으로 안 펴진다.

정답

개념은 힌트 참고.

정답: LL은 왼쪽 자식도 왼쪽이 무거워(bf > 0) 우회전 1회로 해결되지만, LR은 왼쪽 자식이 오른쪽 무거움(bf < 0)이라 자식 좌회전으로 LL 형태로 만든 뒤 부모 우회전이 필요하다.
Q4Insert는 최대 1회 회전인데 Delete는 여러 회전이 필요할 수 있는 이유는?
힌트

회전 후 서브트리의 "높이"가 어떻게 변하는지 생각해 보자.

정답

개념은 힌트 참고.

정답: Delete 후 회전은 서브트리 높이를 1 줄여 상위 노드에 새 불균형을 전파할 수 있어 루트까지 반복 확인이 필요하다. Insert 후 회전은 서브트리 높이를 삽입 전으로 되돌려 전파가 없다.
Q5AVL이 Red-Black Tree보다 높이는 낮은데, 실무에서 Red-Black이 더 많이 쓰이는 이유는?
힌트

균형 조건이 빡빡할수록 검색은 빠르지만 삽입·삭제 비용은 커진다.

정답

개념은 힌트 참고.

정답: 삽입·삭제가 잦은 실무에서는 재균형 비용이 작은 Red-Black이 유리하다. 검색 위주(읽기 중심)라면 더 낮은 높이의 AVL이 유리.
Q6회전 후에도 불균형이 남을 수 있는가?
힌트

Q4와 같은 원리 — 어느 연산에서 전파가 생기는가.

정답

개념은 힌트 참고.

정답: Insert 후 회전은 그 지점에서 완전히 해결되지만, Delete 후 회전은 부모 높이 변화로 상향 불균형이 전파될 수 있어 루트까지 계속 확인해야 한다.

7. 핵심 정리

요약 카드
  • AVL Tree = BST + Height-Balanced (모든 노드 |bf| ≤ 1)
  • 높이 보장: → 검색/삽입/삭제 모두
  • 불균형 유형: LL(우회전), RR(좌회전), LR(좌+우), RL(우+좌)
  • 회전 후 BST 성질(inorder 순서)은 항상 유지
  • Insert: 최대 1회 회전 · Delete: 연쇄 회전 가능
  • 검색 많음 → AVL, 삽입·삭제 많음 → Red-Black
