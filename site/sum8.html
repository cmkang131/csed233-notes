정리본 8. Sorting

단순 정렬 vs 고급 정렬 · 각 알고리즘의 동작 · 언제 무엇을 고를까.

1. 정렬이란 + 알고리즘 지도

정의

Sorting(정렬): (key, info) 쌍으로 이루어진 원소 컬렉션을 key 기준으로 재배열하는 것.

단순 정렬 · O(n²)
  • Bubble Sort(거품 정렬)
  • Selection Sort(선택 정렬)
  • Insertion Sort(삽입 정렬)

구현이 간단, 작은 데이터용.

고급 정렬 · O(n log n)
  • Merge Sort(병합 정렬)
  • Quick Sort(퀵 정렬)
  • Heap Sort(힙 정렬)

구현은 복잡하지만 실무 표준.

특수 정렬
  • Counting Sort(계수 정렬)
  • Radix Sort(기수 정렬)

특정 데이터 타입에서만 가능.

2. 단순 정렬 ()

2.1 Bubble Sort(버블 정렬)

인접한 두 원소를 비교·교환하며 가장 큰 값을 맨 뒤로 떠오르게 한다. 한 Pass마다 맨 뒤 한 칸이 확정.

예제 · [5, 3, 8, 1, 2] 
Pass 1: (5,3)→교환 [3,5,8,1,2] · (5,8)→유지 · (8,1)→교환 · (8,2)→교환
        [3, 5, 1, 2, |8|]  ← 8 확정
Pass 2: (3,5)→유지 · (5,1)→교환 · (5,2)→교환
        [3, 1, 2, |5, 8|]  ← 5 확정
Pass 3: (3,1)→교환 · (3,2)→교환
        [1, 2, |3, 5, 8|]  완성

시간: 최선 , 평균/최악 · 공간 · Stable ✓

2.2 Selection Sort(선택 정렬)

정렬 안 된 부분에서 최솟값을 찾아 맨 앞과 교환한다. 한 Pass마다 맨 앞 한 칸이 확정.

예제 · [5, 3, 8, 1, 2] 
Pass 1: 최솟값 1 → 맨 앞과 swap → [1, 3, 8, 5, 2]
Pass 2: 최솟값 2 → 두 번째와 swap → [1, 2, 8, 5, 3]
Pass 3~: [1, 2, 3, 5, 8] 완성

시간: 항상 · 공간 · Unstable ✗ · swap은 최대 n−1회(Bubble보다 적음)

2.3 Insertion Sort(삽입 정렬)

정렬된 앞부분을 유지하며, 다음 원소를 알맞은 위치에 삽입한다.

예제 · [5, 3, 8, 1, 2] 
[5 | 3, 8, 1, 2]   3 삽입 → [3, 5 | 8, 1, 2]
[3, 5 | 8, 1, 2]   8 삽입 → [3, 5, 8 | 1, 2]
…                → [1, 2, 3, 5, 8] 완성
포인트 · 거의 정렬된 데이터

Insertion Sort는 거의 정렬된 입력에서 에 가깝게 동작한다 — 각 원소가 거의 이동하지 않기 때문. 실무 라이브러리가 작은 구간에서 삽입 정렬로 전환하는 이유.

시간: 최선 , 평균/최악 · 공간 · Stable ✓

3. 고급 정렬 ()

3.1 Merge Sort(병합 정렬) — 분할 정복

  1. 분할: 배열을 반씩 계속 쪼갠다 — 깊이 .
  2. 병합: 두 정렬된 조각을 합치며 정렬 — 각 층 .
예제 · [5, 3, 8, 1, 2, 9] 
분할: [5,3,8] [1,2,9] → [5,3][8] [1,2][9] → [3][5] …
병합: [3,5] + [8] → [3,5,8] · [1,2] + [9] → [1,2,9]
      [3,5,8] + [1,2,9] → [1, 2, 3, 5, 8, 9]

시간: 항상 — 최악에도 보장 · 공간 (임시 배열) · Stable ✓ · 실시간 시스템에 적합

Non-recursive Merge Sort (Bottom-up)

재귀 분할 없이, 배열을 이미 쪼개져 있다고 보고 width = 1, 2, 4, … 단위로 이웃 조각을 병합해 올라간다. 각 단계 , 단계 수 → 총 . 재귀 호출 오버헤드와 stack overflow 위험이 없어 대용량에 유리.

예제 · [5, 3, 8, 1, 2, 9] 
width 1: [5][3] [8][1] [2][9] → [3,5] [1,8] [2,9]
width 2: [3,5] [1,8] → [1,3,5,8] · [2,9]
width 4: [1,3,5,8] + [2,9] → [1, 2, 3, 5, 8, 9]

3.2 Quick Sort(퀵 정렬) — Pivot 기반 분할

  1. Pivot 선택(예: 맨 왼쪽 또는 중간값).
  2. 분할: pivot보다 작은 것 | pivot | 큰 것으로 나눈다 — .
  3. 양쪽을 재귀 정렬. pivot이 잘 갈라지면 깊이 .
예제 · [5, 3, 8, 1, 2], pivot = 5 
<5: [3,1,2]  =5: [5]  >5: [8]
재귀: [3,1,2] → [1,2,3]
최종: [1, 2, 3, 5, 8]

시간: 평균 , 최악 (pivot 선택 실패 시) · 공간 (재귀 스택) · Unstable ✗ · 실제로는 가장 빠름(캐시 효율)

In-place Partitioning (Two-Pointer Scan)

양 끝 포인터 L, R이 서로를 향해 이동하며 교환. L은 pivot 이상인 값, R은 pivot 미만인 값을 찾아 멈춘다.

예제 · [17, 20, 17, 33, 15, 2, 21, 14], pivot = 17 
L: 20(≥17) 발견, R: 14(<17) 발견 → swap
  [17, 14, 17, 33, 15, 2, 21, 20]
L: 17 발견, R: 2 발견 (21은 ≥17이라 스킵) → swap
  [17, 14, 2, 33, 15, 17, 21, 20]
L: 33 발견, R: 15 발견 → swap
  [17, 14, 2, 15, 33, 17, 21, 20]
L과 R이 엇갈림 → pivot을 R 위치(15)와 교환
  [15, 14, 2] | 17 | [33, 17, 21, 20]
→ 좌우를 각각 재귀 → 최종 [2, 14, 15, 17, 17, 20, 21, 33]
함정 · 엇갈린 뒤의 마지막 교환

스캔이 끝나면 pivot은 R이 가리키는 위치와 교환한다(L이 아니라 R). 그래야 pivot 왼쪽이 모두 pivot 이하가 된다.

5. 어떤 정렬을 고를까

데이터 크기별
  • 작은 데이터 (n < 50) → Insertion: 단순, 오버헤드 최소
  • 중간 데이터 (50 < n < 1M) → Quick: 평균 최고 속도
  • 큰 데이터 (n > 1M) → Merge: 최악 성능 보장
데이터 특성별
  • 거의 정렬됨 → Insertion (에 근접)
  • 안정성 필수(다중 키 정렬) → Merge / Bubble / Insertion
  • 메모리 제약(임베디드) → Quick / Heap
  • 최악 성능 보장 필요(실시간, 금융) → Merge / Heap
