Ch3. Algorithm Analysis — Big-O & 점근 분석

1. Algorithm(알고리즘) 비교: 왜 필요한가

이론 & 배경

  • Algorithm: 유한 시간 내 문제를 해결하는 step-by-step 절차.
  • 같은 문제에 여러 알고리즘 → 어느 것이 더 나은가?
  • 비교 척도 = 효율성(Efficiency)
    • Time complexity(시간복잡도): 실행 시간
    • Space complexity(공간복잡도): 메모리 사용량

두 가지 비교 방법

방법 장점 한계
Empirical(경험적 분석) (실제 실행) 구체적 성능 수치 구현 비용, 입력 의존, 동일 HW/SW 필요
Theoretical(이론적 분석) (이론 분석) HW/SW 독립, 모든 입력 고려 상수항 무시로 실제와 괴리 가능
  • 이론 분석: 입력 크기 에 대한 running time/space를 함수로 표현.

주의점

7. Amortized(분할 상환) Analysis (분할 상환)

동기

  • put(x) 연산이 가끔 배열 확장 필요 → worst case 이지만 매번 그런 건 아님
  • 평균 비용을 n번 call에 대해 계산:

두 버전 비교

Version 1: 크기 +5씩 증가 (상수 증가)

확장은 5번마다 → 5, 10, 15, ... 크기 복사. 총 비용 유도 ( 번 put):

Total = n + (0 + 5 + 10 + ... + 5(m-1))
      = n + 5 · m(m-1)/2
      ≈ n + n²/10                    ← ∵ m = n/5

amortized = (n + n²/10)/n = 1 + n/10 = O(n)

→ call당 O(n). 나쁨.

Version 2: 크기 × 2 (더블링)

확장은 이 2의 거듭제곱일 때 → 1, 2, 4, 8, ... 복사. 총 비용 ():

Total ≈ n + (1 + 2 + 4 + ... + 2^(k-1))
      ≈ n + (2^k - 1)     ← 기하급수 합
      ≈ 2n - 1

amortized = (2n-1)/n = 2 - 1/n = O(1)

→ call당 O(1). 좋음.

교훈

상수 증가 → per call, 더블링 → per call. 같은 worst case 이라도 amortized 관점에서 전혀 다른 성능.
