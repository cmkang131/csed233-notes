2. Height-Balanced 정의

두 가지 수준의 balance

Perfectly balanced: 모든 level이 꽉 참 (= 모든 내부 노드 자식 2개 + 모든 leaf가 같은 level; 같은 level만으로는 full이 아님). 높이가 h이면 노드 수가 정확히 2h+1-1이어야 하므로, 노드 한 개 삽입만으로 perfect 상태를 유지하는 것은 일반적으로 불가능하다. 그래서 완화된 height-balanced 조건을 쓴다.

(Almost) Height-Balanced: 각 노드 에 대해 두 subtree의 높이 차 ≤ 1, 그리고 두 subtree도 재귀적으로 height-balanced → AVL tree 조건.

Height 규약

  • 단일 노드: height = 0
  • 빈 tree: height = (non-existing subtree)
  • → Balance factor 계산 시 일관성 유지

4. Insertion: 기본 절차

2단계

  1. BST insert: 일반 BST 방식으로 leaf에 추가
  2. Rebalance: 새 노드에서 root 방향으로 올라가며 balance factor 체크, 위반 시 rotation

핵심 관찰

  • Insert 후 balance 변화는 경로상의 노드만 (leaf → root 경로)
  • 첫 번째 violation 노드 = Pivot () → 가장 깊은 unbalanced node
  • 이 pivot에서만 rotation하면 전체 복구 보장 (증명: rotation 후 subtree 높이가 insert 이전과 같아짐)

5. Imbalance 4 Types

4가지 경우 (pivot = )

Type 의미 사례
LL 의 left child의 left subtree에 삽입 left-left 편향
RR 의 right child의 right subtree에 삽입 right-right 편향
LR 의 left child의 right subtree에 삽입 zig-zag
RL 의 right child의 left subtree에 삽입 zig-zag

Rotation(회전) 종류

  • Single rotation: LL, RR (pivot 한 번만 회전)
  • Double rotation: LR, RL (두 번: 먼저 child 회전, 다음 pivot 회전)
    • LR = RR + LL: child에 RR 먼저, 그 다음 pivot에 LL
    • RL = LL + RR: child에 LL 먼저, 그 다음 pivot에 RR

왜 LR, RL은 double rotation?

  • LR 형태를 single LL rotation만 하면 여전히 불균형
  • 먼저 중간 child에 RR로 돌려 → LR을 'LL 형태로 변환' → 그 다음 LL

전제: 각 노드에 subtree height를 저장한다고 가정하면 height 갱신과 BF 계산은 노드당 O(1)이고, 경로상 유지 비용 전체는 O(log n)이다. 저장된 높이가 없으면 노드당 O(1)이 성립하지 않는다.

Early termination

  • 재균형은 최대 한 위치에서만 수행 (기본 회전은 LL/RR 1번, LR/RL 2번)
  • 재균형 후 해당 subtree 높이가 insert 이전 높이로 복귀
  • → 그 위 조상들의 bf 변화 없음 → 즉시 종료 가능 (early termination)

9. Deletion

절차

  1. BST deletion 수행 (leaf/deg-1/deg-2 case 처리 — Ch9)
  2. 실제 삭제된 노드 위치에서 root 방향으로 bf 체크
  3. Violation 발생하면 적절한 rotation
  4. Insertion과 달리, 여러 번 rotation이 필요할 수 있음 (계속 위로 올라가며 체크)

Q1왜 insert는 rotation 1번, delete는 여러 번?
힌트

회전이 서브트리의 "높이"를 어떻게 바꾸는지가 핵심이다.

정답

개념은 힌트 참고.

  • Insert 후 rotation: subtree 높이가 insert 이전과 동일해짐 → 조상 영향 없음
  • Delete 후 rotation: subtree 높이가 1 감소할 수 있음 → 조상도 unbalanced 될 수 있음 → 계속 올라가며 체크
Q2일반 BST가 AVL보다 실전에서 빠른 경우?
힌트

AVL의 bf 관리와 회전은 상수 비용이 크다. 균형이 이미 보장된다면?

정답

개념은 힌트 참고.

  • 무작위 순열로 삽입하면 기대 높이와 기대 탐색은 O(log n)이지만 AVL 균형 조건을 보장하지 않으며 worst-case는 여전히 O(n)이다. 입력이 이미 random이면 일반 BST도 , rotation 오버헤드 없음
  • AVL은 매 삽입/삭제마다 bf 관리 + rotation → 상수항 큼. worst-case 보장이 중요하지 않고 실제 높이가 낮다면, 회전·BF 유지 비용이 없는 일반 BST가 빠를 수 있다
  • → 'worst case 보장이 필요 없는' 경우 일반 BST도 실용적
