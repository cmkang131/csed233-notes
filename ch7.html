Ch7. Priority Queue & Heap

1. Priority Queue (PQ): 동기

Queue에 우선순위 추가

  • 일반 Queue(큐): FIFO — 들어온 순서대로 나감
  • Priority Queue(우선순위 큐): 각 원소에 priority(key) 부여 → priority 순으로 나감
  • Priority는 unique일 필요 없음
  • 핵심 연산:
    • : 임의 원소 삽입
    • : 최우선 원소 꺼내기 =

왜 필요한가

  • 응급실 환자 분류, OS 프로세스 스케줄링, Dijkstra 최단경로, 이벤트 시뮬레이션 등
  • 현실은 FIFO보다 우선순위 기반 처리가 더 자연스러움

3. Binary Heap: 정의

두 가지 Property

Min-Heap은 다음 두 조건을 만족하는 tree:

  1. Structural property: Complete Binary Tree (CBT)
    • → array로 pointer 없이 저장 가능 (Ch5 numbering 활용)
  2. Heap-order property: Min-tree
    • for all nodes
    • → root가 전체 최솟값
      Max-Heap: (2')만 부등호 반대

CBT(완전 이진 트리) 선택 이유

  • Heap의 모든 연산은 결국 트리 '높이'만큼 이동 → 높이 최소화가 관건
  • CBT는 개 노드로 최소 높이 보장
  • 또한 array 저장으로 pointer 오버헤드 제거 (cache friendly)

Heap ≠ BST(이진 탐색 트리)

  • Heap은 같은 level 내 순서에 제약 없음 (left/right 구분 의미 없음)
  • BST는 left < root < right 이지만, heap은 parent ≤ children만 요구

4. Insert: Up-Heap Bubbling

2단계 알고리즘

  1. Hole 생성: CBT 구조 유지 위해 최하위 level의 가장 오른쪽에 새 노드 slot 추가 → array 끝에 append
  2. Up-heap bubbling: heap-order 복원 위해 새 원소를 parent와 비교하며 위로 swap

시간복잡도 유도

  • Bubbling은 tree 높이만큼만 위로 올라감
  • CBT 높이

  • → Insert =

5. DeleteMin: Down-Heap Bubbling

2단계 알고리즘

  1. Root 제거 & 마지막 원소 이동: root 삭제 → 최하위 최우측 원소를 root 자리로
  2. Down-heap bubbling: heap-order 복원 위해 더 작은 자식과 비교하며 아래로 swap

왜 '더 작은' 자식과 비교?

  • 새 parent 자리에 오는 값이 두 자식 중 작은 쪽이어야 heap-order 유지
  • 큰 자식과 swap하면 다른 쪽 자식 조건 위반
  • → 반드시 min(left, right)과 비교 후 swap

시간복잡도

  • 트리 높이만큼 내려감 →

6. Quiz 정리

Q1Min-heap의 heap-order property의 정확한 정의는?
힌트

Heap의 조건은 structural(모양)과 heap-order(값 관계) 두 가지다. 어느 쪽을 묻는지 구분하자.

정답

개념은 힌트 참고.

  • A. Every parent node has value ≤ its children ✓
  • B. 모든 level이 꽉 참 → X (structural property와 혼동, 이건 full의 정의)
  • C. Root가 최댓값 → X (min-heap은 root가 최솟값)
  • D. Insertion은 root에서 → X (insertion은 맨 끝에서)
정답: A — Every parent node has value ≤ its children.
